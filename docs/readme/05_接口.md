# 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/` | 否 | 健康检查 |
| POST | `/chat` | ✅ Bearer token | 普通对话（`thread_id` 必填） |
| POST | `/chat/stream` | ✅ Bearer token | 流式对话（SSE） |
| GET | `/history` | ✅ Bearer token | 查看对话历史（只返回自己租户的） |

### 鉴权

除 `/` 外的接口都要带：

```text
Authorization: Bearer <API_KEY>
```

配置多个 `API_KEYS` 时，**每个 key 是一个独立租户**：

- 记忆按 `"{租户}:{thread_id}"` 命名空间隔离
- `/history` 只返回 `owner = 当前租户` 的记录

### 请求示例

```bash
# 普通对话（带鉴权 + thread_id 区分会话）
curl -X POST http://127.0.0.1:8000/chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-secret-key-here" \
  -d '{"message": "MCP 是什么？", "thread_id": "user_001"}'

# 流式对话
curl -X POST http://127.0.0.1:8000/chat/stream \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-secret-key-here" \
  -d '{"message": "MCP 是什么？", "thread_id": "user_001"}'

# 查看历史（需要鉴权）
curl "http://127.0.0.1:8000/history?thread_id=user_001" \
  -H "Authorization: Bearer your-secret-key-here"
```

### 多轮对话演示

```bash
# 第一轮
curl -X POST http://127.0.0.1:8000/chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-secret-key-here" \
  -d '{"message": "MMR 是什么？", "thread_id": "test_001"}'

# 第二轮（用代词指代）
curl -X POST http://127.0.0.1:8000/chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-secret-key-here" \
  -d '{"message": "它和普通相似度检索有什么区别？", "thread_id": "test_001"}'

# 重启服务后再问，仍能理解"它"指 MMR
# docker compose down && docker compose up -d 后依然成立（checkpoints volume 持久化）
```
