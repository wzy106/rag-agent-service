# 阈值标定

`MAX_DISTANCE` 通过正负样本的 `best_distance` 分布和 PR 曲线标定，不是拍脑袋定的。

## 方法

- 正样本：从测试集抽样（默认 100 条，seed=42）
- 负样本分两组：
  - `eval/negatives.json`：明显离题的问题（天气、菜谱、电影）
  - `eval/negatives_hard.json`：近域但库内没有的问题（版本号、新特性、价格）
- 对每条问题算 top-1 的 L2 距离
- 扫 0.50–1.50 共 101 个候选阈值，计算 Precision / Recall / F1
- 画距离分布图和 PR 曲线

## 口径（重要）

这里衡量的是**检索层是否接受一个 query**，不是端到端幻觉率。

- `FPR = FP / (FP + TN)`：负样本被接受的比例。
- `FDR = FP / (TP + FP)`：被接受的结果里负样本占的比例。
- FDR 依赖正负样本的抽样基率；`100 正 + 25 负` 的基率不是真实流量基率。
- 旧文档把 `1 - precision` 写成“幻觉率 1%”，这个说法不准确，已修正。

因此标定输出会分别报告 easy / hard / combined 的 FPR，而不是一个“幻觉率”。

## 当前限制

- 阈值只看向量 top-1，且在 BM25/RRF 融合之前判断；关键词强相关但向量距离大的 query 会被提前拒绝。
- 近域但库内没有的问题可能通过阈值，进入生成阶段；真正的拒答需要在生成层做充分性判断或 graph 分支。
- 这些是检索/生成链路的已知问题，不应由“阈值标定”单独背锅。

## 复现

```bash
python eval/calibrate_distance.py \
  --positives eval/test_set_v3_gold.json \
  --negatives eval/negatives.json eval/negatives_hard.json \
  --output eval/output/calibration_v3.json
```

输出：

- `eval/output/calibration_v3.json`（当前阈值、F1 最大点、扫描曲线、距离分布）
- `eval/output/distance_distribution.png`
- `eval/output/pr_curve.png`

具体数值以根目录 `README.md` 和 `eval/output/calibration_v3.json` 为准。
