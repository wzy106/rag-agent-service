# 测试集自动生成

v3 测试集由 `scripts/generate_testset.py` 生成：

1. 遍历索引里的所有 chunk，按 `source` 分组
2. 每篇文档取最长的 2 个 chunk
3. 调 DeepSeek API 生成 3 个中文问题
4. 每条问题必须标注 `evidence`：
   - `[0]` 或 `[1]`：一个片段就能回答
   - `[0, 1]`：必须同时使用两个片段
5. 写入 `evidence_chunk_ids` 和 `evidence_coverage_mode`（any/all）

示例：

```json
{
  "question": "create_agent 的 checkpointer 参数是干嘛用的？",
  "expected_sources": ["langchain/02_二create_agent_的参数.md"],
  "evidence_chunk_ids": ["<chunk_id>"],
  "evidence_coverage_mode": "any",
  "generator_version": "v3-evidence"
}
```

## 多金标扩展

语料里同一结论经常出现在多篇文档（项目笔记、面试题拆分、踩坑故事）。如果只认生成问题的那一个 chunk，系统命中了另一篇文档里的等价答案也会被判错。

`scripts/label_gold.py` 做两步：

1. 对每个 evidence chunk，计算它和其他 chunk 的 3-gram Jaccard；
2. 把 Jaccard ≥ 0.8 的 chunk 加入 `gold_chunk_ids`，对应 source 加入 `gold_sources`。

同时用 0.6 阈值跑一遍作为敏感度统计，但不改主标签。输出：

- `eval/test_set_v3_gold.json`
- `eval/test_set_v3_gold.stats.json`（标签歧义率、额外标签数）

## 成本

- 约 ¥0.2–0.5（98 篇 × 1 次 API 调用）
- 并发 5 时约 2–5 分钟
- 失败文档会回退到 v2 的对应问题，并把两个 chunk 都标为 evidence（保守口径），在 `generator_version` 里标记 `v3-fallback-v2`

## 注意

- v2 测试集（`eval/test_set_v2.json`）保留，便于历史对比；新评估默认用 v3 gold 文件。
- 索引或切分参数变更后必须重新生成，否则 `evidence_chunk_ids` 会失效。`scripts/build_index.py --check` 和 `tests/test_index_consistency.py` 用来发现索引漂移。
